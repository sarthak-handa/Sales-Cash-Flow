How a sales-file row is matched to SAP
  1. SAP is netted per WBS element (one WBS = one assembly). Part bills, cancellations (S1), credit memos (G2) and re-bills are added up, so a cancelled-and-re-billed item counts once. Its billed in month is the month of its last invoice.
  2. Names are cleaned before comparing: project prefix, ASSY/ASSEMBLY, #01 → #1, ACC. → accumulator, delivery = exit, BUP = backup, WR = work roll, tension reel (entry/delivery) = ETR/DTR, and so on. SAP's WBS description and every product name billed under it are compared.
  3. Opposites never match: uncoiler/recoiler, entry/exit, top/bottom, fixed/moving, POR/ETR/DTR, or different numbers (#2 vs #3).
  4. Best pairs first, scored on name, then helped by equal value and a close month.
  5. Values that add up: SAP often bills several sales rows under one WBS (e.g. "BUP chocks ₹15 L" + "BUP bearings ₹30 L" = SAP "Top & bottom backup roll chock ₹45 L"), or one row under several WBS. These are only linked for rows already marked Disp., so they never raise a red flag on their own.
  6. Same value, same month, names unrelated: linked but labelled "check".

Anything still unmatched can be linked or unlinked by hand from the row's detail. Your links are kept in planner/recon_overrides.json and survive new SAP exports.
